# Contributing to DrivX

We welcome contributions from the community. DrivX is built in the open.

## How to Contribute

### Reporting Issues
- Use GitHub Issues for bugs, feature requests, or questions
- Include steps to reproduce for bugs
- Tag issues appropriately (bug, enhancement, question)

### Code Contributions
1. Fork the repository
2. Create a feature branch (`git checkout -b feature/your-feature`)
3. Commit your changes (`git commit -m 'Add feature'`)
4. Push to the branch (`git push origin feature/your-feature`)
5. Open a Pull Request

### Documentation
- Improvements to specs, whitepaper, or README are always welcome
- Translations of documentation are appreciated

## Code of Conduct

- Be respectful and constructive
- No spam, harassment, or off-topic promotion
- Focus on technical merit in code reviews

## Security

If you discover a security vulnerability, please report it privately via email rather than opening a public issue. Details on responsible disclosure will be published before mainnet launch.
